## 1. Firestore Database Overview

### 1.1 Design Principles
- All timestamps are Firestore `Timestamp` type using **server timestamps** (`FieldValue.serverTimestamp()`). Never use device local time for timestamps written to Firestore.
- All string enum values use **lowercase with underscores** (e.g., `over_current`, not `Overcurrent`, not `OVER_CURRENT`).
- Fields that are intentionally absent or unknown use **`null`** — never empty strings, never `0` as a null substitute.
- The `devices` document is **never created by factory pre-registration**. It is created by the Flutter app during the BLE provisioning step, using metadata pulled directly from the ESP32.
- The `devices` document is **never deleted** — only `ownerUid` is nulled when ownership is severed.

### 1.2 Collection Structure Overview
```
Firestore Root
├── users/                          # One document per user account
│   └── {uid}/                      # Document ID = Firebase Auth UID
│
├── devices/                        # One document per physical ESP32 unit
│   └── {serialNumber}/             # Document ID = serial number (e.g. OHM00123456)
│       ├── telemetry/              # Subcollection — single document
│       │   └── latest              # FIXED document ID — always overwritten
│       └── errors/                 # Subcollection — one document per error event
│           └── {auto-id}/
│
└── alerts/                         # One document per push notification sent
    └── {auto-id}/
```

## 2. Collection: `users`

**Path:** `users/{uid}`
**Document ID:** Firebase Auth UID (auto-generated by Firebase Auth)
**Created by:** Flutter app on successful Sign Up
**Updated by:** Flutter app (name, dob, fcmToken), Cloud Functions (fcmToken deletion)
**Deleted by:** Cloud Function `deleteAccount` only — never by the Flutter app directly

### 2.1 Fields

| Field | Type | Nullable | Required | Description |
|-------|------|----------|----------|-------------|
| `name` | `string` | No | Yes | User's full name. Max 60 characters. |
| `email` | `string` | No | Yes | User's email address. Must match Firebase Auth email. |
| `dob` | `Timestamp` | No | Yes | Date of birth. Used for age verification (≥ 13 years). |
| `deviceSerial` | `string` | **Yes** | No | Serial number of currently paired device. `null` if no device paired. **One device per user — single string, never an array.** |
| `fcmToken` | `string` | **Yes** | No | Current FCM registration token. `null` if user denied notification permission or token is invalid. |
| `createdAt` | `Timestamp` | No | Yes | Account creation timestamp. Set once on document creation, never updated. Uses `FieldValue.serverTimestamp()`. |

### 2.2 Write Operations

**On Sign Up (Flutter app):**
```javascript
await db.collection('users').doc(uid).set({
  name: name,
  email: email,
  dob: Timestamp.fromDate(dob),
  deviceSerial: null,
  fcmToken: null,  // Updated on first app launch after auth
  createdAt: FieldValue.serverTimestamp(),
});
```

**On FCM token update (Flutter app, every launch):**
```javascript
await db.collection('users').doc(uid).update({
  fcmToken: newToken,
});
```

**On device pairing (Flutter app, after provisioning):**
```javascript
await db.collection('users').doc(uid).update({
  deviceSerial: serialNumber,
});
```

**On profile update (Flutter app):**
```javascript
await db.collection('users').doc(uid).update({
  name: newName,
  dob: Timestamp.fromDate(newDob),
});
```

## 3. Collection: `devices`

**Path:** `devices/{serialNumber}`
**Document ID:** Serial number of the physical ESP32 (e.g., `OHM00123456`)
**Created by:** Flutter app during BLE provisioning (metadata pulled from ESP32)
**Updated by:** Flutter app (friendlyName, ownerUid, provisioned), ESP32 firmware (connectedSsid, firmwareVersion, lastTelemetry via telemetry/latest)
**Never deleted**

### 3.1 Fields

| Field | Type | Nullable | Required | Description |
|-------|------|----------|----------|-------------|
| `ownerUid` | `string` | **Yes** | No | Firebase Auth UID of the paired user. `null` when device is unowned (factory state, after Remove Device, or after Delete Account). |
| `provisioned` | `boolean` | No | Yes | `true` if ESP32 has received and stored Wi-Fi credentials. `false` at factory/creation. **Set to `true` only during provisioning. Reset to `false` only by `removeDevice` Cloud Function with `forceReprovision: true`.** |
| `friendlyName` | `string` | No | Yes | User-editable display name shown in Dashboard app bar. Default: `"Ohmitron Battery"`. Max 30 characters. |
| `deviceModel` | `string` | No | Yes | Hardware model identifier. Set during provisioning from ESP32 metadata. Example: `"OHM-BMS-100"`. |
| `firmwareVersion` | `string` | No | Yes | ESP32 firmware version string. Set during provisioning, updated by ESP32 on each boot. Example: `"1.2.4"`. |
| `bmsModel` | `string` | No | Yes | BMS model identifier. Set during provisioning from ESP32 metadata. |
| `bmsId` | `string` | No | Yes | BMS unique identifier. Set during provisioning from ESP32 metadata. |
| `connectedSsid` | `string` | **Yes** | No | SSID of the Wi-Fi network the ESP32 is connected to. Updated by ESP32 on each successful connection or reconnection. `null` if not yet connected. |
| `createdAt` | `Timestamp` | No | Yes | When the devices document was first created. Set once during provisioning. |

### 3.2 Write Operations

**On provisioning — document creation (Flutter app):**
```javascript
await db.collection('devices').doc(serialNumber).set({
  ownerUid: uid,
  provisioned: false,  // Set to true in step 6 of provisioning
  friendlyName: 'Ohmitron Battery',
  deviceModel: metadataFromESP32.deviceModel,
  firmwareVersion: metadataFromESP32.firmwareVersion,
  bmsModel: metadataFromESP32.bmsModel,
  bmsId: metadataFromESP32.bmsId,
  connectedSsid: null,
  createdAt: FieldValue.serverTimestamp(),
});
```

**On provisioning complete — set provisioned flag (Flutter app):**
```javascript
await db.collection('devices').doc(serialNumber).update({
  provisioned: true,
  ownerUid: uid,
});
```

**On friendly name update (Flutter app — only permitted write from app side):**
```javascript
await db.collection('devices').doc(serialNumber).update({
  friendlyName: newName,
});
```

**On ESP32 boot — firmware version update (ESP32 via service account):**
```javascript
await db.collection('devices').doc(serialNumber).update({
  firmwareVersion: currentVersion,
  connectedSsid: currentSsid,
});
```

## 4. Subcollection: `devices/{serial}/telemetry`

**Path:** `devices/{serialNumber}/telemetry/latest`
**Document ID:** **FIXED — always `"latest"`**. This document is always overwritten, never appended to.
**Written by:** ESP32 firmware via Firebase REST API every 30 seconds
**Read by:** Flutter app every 30 seconds via `.get()`
**Never deleted**

### 4.1 Why a Single Document
The Dashboard only ever needs the most recent telemetry reading. Storing 2,880 documents per device per day when only one is ever read is unnecessary cost. A single overwritten document gives identical read behaviour at a fraction of the Firestore cost.

### 4.2 Fields

| Field | Type | Nullable | Required | Description |
|-------|------|----------|----------|-------------|
| `timestamp` | `Timestamp` | No | Yes | When this measurement was taken. **Must use `FieldValue.serverTimestamp()`.** This is used by the Flutter app to detect stale data (> 45 seconds since last write). |
| `stateOfCharge` | `number` | **Yes** | No | Battery state of charge as a percentage (0.0–100.0). `null` if BMS does not expose SOC. Required for "Low battery" push notification trigger. |
| `remainingTimeHours` | `number` | **Yes** | No | Estimated remaining runtime in fractional hours. `null` if not calculable (e.g., while charging). Example: `3.7` = 3h 42m. |
| `voltage` | `number` | No | Yes | Pack voltage in Volts. Raw BMS value. Example: `48.6`. |
| `current` | `number` | No | Yes | Pack current in Amps. Positive = discharging, Negative = charging. Raw BMS value. Example: `12.3`. |
| `dischargingWatts` | `number` | **Yes** | No | Instantaneous power draw in Watts (`voltage × current`). `null` or `0` if charging. Calculated by ESP32 firmware. |
| `isCharging` | `boolean` | No | Yes | `true` if BMS indicates charging state. |
| `isDischarging` | `boolean` | No | Yes | `true` if BMS indicates discharging state. `isCharging` and `isDischarging` are mutually exclusive — both cannot be `true` simultaneously. |
| `balanceState` | `string` | No | Yes | One of: `"inactive"`, `"active"`, `"balancing"`. |
| `protectionState` | `string` | No | Yes | One of: `"none"`, `"over_current"`, `"over_voltage"`, `"under_voltage"`, `"over_temperature"`, `"short_circuit"`. |
| `temperatureCelsius` | `number` | No | Yes | Battery pack temperature in degrees Celsius. Example: `28.5`. |

### 4.3 Stale Data Detection Logic (Flutter App)
```dart
// After every successful read of telemetry/latest:
final serverTimestamp = telemetryDoc.data()['timestamp'] as Timestamp;
final lastUpdate = serverTimestamp.toDate();
final isStale = DateTime.now().difference(lastUpdate).inSeconds > 45;

// Display StaleDataBanner when isStale = true
// Note: DateTime.now() is the phone local time
// This is acceptable because server timestamps and device time
// are typically within 1-2 seconds of each other.
// In production, use Firestore.instance.snapshotInSync for precise drift detection.
```

### 4.4 ESP32 Write Pattern
```
Every 30 seconds:
  POST to Firebase REST API:
  PUT /v1/projects/{project}/databases/(default)/documents/
      devices/{serial}/telemetry/latest
  
  Body: { fields: { all telemetry fields } }
  
  Separately (on boot and on network reconnection):
  PATCH /v1/projects/{project}/databases/(default)/documents/
        devices/{serial}
  
  Body: { fields: { firmwareVersion, connectedSsid } }
```

## 5. Subcollection: `devices/{serial}/errors`

**Path:** `devices/{serialNumber}/errors/{auto-id}`
**Document ID:** Auto-generated by Firestore
**Written by:** ESP32 firmware via Firebase REST API when a BMS error occurs
**Read by:** Flutter app — latest 20 only
**Never deleted** (error history is permanent for support purposes)

### 5.1 Fields

| Field | Type | Nullable | Required | Description |
|-------|------|----------|----------|-------------|
| `timestamp` | `Timestamp` | No | Yes | When the error occurred on the BMS. Uses `FieldValue.serverTimestamp()`. |
| `errorCode` | `string` | No | Yes | Short error code. See error code registry below. Example: `"E001"`. |
| `message` | `string` | No | Yes | Human-readable error description. Example: `"Cell overvoltage detected"`. |
| `severity` | `string` | No | Yes | One of: `"info"`, `"warning"`, `"critical"`. |

### 5.2 Error Code Registry

| Code | Message | Severity |
|------|---------|----------|
| `E001` | Cell overvoltage detected | `critical` |
| `E002` | Cell undervoltage detected | `critical` |
| `E003` | Pack overtemperature | `critical` |
| `E004` | Overcurrent on discharge | `warning` |
| `E005` | Cell imbalance detected | `warning` |
| `E006` | Short circuit protection triggered | `critical` |
| `E007` | BMS communication timeout | `info` |

*Additional codes will be added by the firmware team. This table is the current V1 registry.*

### 5.3 Query Pattern (Flutter App)
```dart
final query = db
  .collection('devices')
  .doc(serialNumber)
  .collection('errors')
  .orderBy('timestamp', descending: true)
  .limit(20);

final snapshot = await query.get();
```

## 6. Collection: `alerts`

**Path:** `alerts/{auto-id}`
**Document ID:** Auto-generated by Firestore
**Created by:** Cloud Functions only — never by the Flutter app
**Read by:** Flutter app (filtered by uid AND deviceSerial)
**Updated by:** Flutter app (mark as read — `read` field only)
**Deleted by:** Flutter app (individual delete, clear all), Cloud Functions (`removeDevice`, `deleteAccount`)

### 6.1 Fields

| Field | Type | Nullable | Required | Description |
|-------|------|----------|----------|-------------|
| `targetUserUid` | `string` | No | Yes | Firebase Auth UID of the user to notify. |
| `deviceSerial` | `string` | No | Yes | Serial number of the device that triggered this alert. Used to scope notifications to the current device only. |
| `title` | `string` | No | Yes | Short notification title. Example: `"High Temperature Alert"`. |
| `body` | `string` | No | Yes | Notification body text. Example: `"Your battery temperature has reached 65°C."`. |
| `timestamp` | `Timestamp` | No | Yes | When the alert was created by the Cloud Function. Uses `FieldValue.serverTimestamp()`. |
| `read` | `boolean` | No | Yes | `false` when created. Set to `true` by Flutter app when user taps the notification. |

### 6.2 Query Pattern (Flutter App)
```dart
final query = db
  .collection('alerts')
  .where('targetUserUid', isEqualTo: uid)
  .where('deviceSerial', isEqualTo: serialNumber)
  .orderBy('timestamp', descending: true);

final snapshot = await query.get();
```

**This query requires a composite index.** See Section 8.

## 7. Firestore Security Rules

**File:** `firestore.rules`

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // ─────────────────────────────────────────────
    // USERS COLLECTION
    // Users can only read and write their own document
    // ─────────────────────────────────────────────
    match /users/{userId} {
      allow read: if request.auth != null
                  && request.auth.uid == userId;

      allow create: if request.auth != null
                    && request.auth.uid == userId
                    && request.resource.data.keys().hasAll([
                         'name', 'email', 'dob', 'createdAt'
                       ])
                    && request.resource.data.name is string
                    && request.resource.data.email is string;

      allow update: if request.auth != null
                    && request.auth.uid == userId
                    && request.resource.data.diff(resource.data)
                         .affectedKeys()
                         .hasOnly(['name', 'dob', 'fcmToken',
                                   'deviceSerial']);

      allow delete: if false; // Cloud Function only
    }

    // ─────────────────────────────────────────────
    // DEVICES COLLECTION
    // Owner can read their device
    // Owner can create during provisioning
    // Owner can update friendlyName only
    // ─────────────────────────────────────────────
    match /devices/{serial} {
      allow read: if request.auth != null
                  && (resource == null
                      || resource.data.ownerUid == request.auth.uid
                      || resource.data.ownerUid == null);

      allow create: if request.auth != null
                    && request.resource.data.ownerUid == request.auth.uid;

      allow update: if request.auth != null
                    && resource.data.ownerUid == request.auth.uid
                    && request.resource.data.diff(resource.data)
                         .affectedKeys()
                         .hasOnly(['friendlyName', 'provisioned',
                                   'ownerUid']);
                    // Note: provisioned and ownerUid updates during
                    // provisioning flow are permitted.
                    // All other field updates are Cloud Function only.

      allow delete: if false; // Never deleted
    }

    // ─────────────────────────────────────────────
    // TELEMETRY SUBCOLLECTION
    // Owner can read — ESP32 writes via service account
    // ─────────────────────────────────────────────
    match /devices/{serial}/telemetry/{docId} {
      allow read: if request.auth != null
                  && get(/databases/$(database)/documents/devices/$(serial))
                       .data.ownerUid == request.auth.uid;

      allow write: if false; // ESP32 service account only
    }

    // ─────────────────────────────────────────────
    // ERRORS SUBCOLLECTION
    // Owner can read — ESP32 writes via service account
    // ─────────────────────────────────────────────
    match /devices/{serial}/errors/{docId} {
      allow read: if request.auth != null
                  && get(/databases/$(database)/documents/devices/$(serial))
                       .data.ownerUid == request.auth.uid;

      allow write: if false; // ESP32 service account only
    }

    // ─────────────────────────────────────────────
    // ALERTS COLLECTION
    // Owner can read, update read flag, delete their alerts
    // Cloud Functions create alerts
    // ─────────────────────────────────────────────
    match /alerts/{alertId} {
      allow read: if request.auth != null
                  && resource.data.targetUserUid == request.auth.uid;

      allow update: if request.auth != null
                    && resource.data.targetUserUid == request.auth.uid
                    && request.resource.data.diff(resource.data)
                         .affectedKeys()
                         .hasOnly(['read']);
                    // Users may only toggle the read field

      allow delete: if request.auth != null
                    && resource.data.targetUserUid == request.auth.uid;

      allow create: if false; // Cloud Functions only
    }
  }
}
```

## 9. Cloud Functions — All 4 Functions

**Runtime:** Node.js 20 (Firebase Functions v2)
**Region:** `us-central1` (default) — confirm with supervisor if different region needed
**Language:** TypeScript

### 9.1 Function 1 — `onTelemetryWrite` (Push Notification Trigger)

**Trigger:** `onDocumentWritten` on `devices/{serial}/telemetry/latest`
**Purpose:** Evaluate push notification conditions on every telemetry update

```typescript
export const onTelemetryWrite = onDocumentWritten(
  'devices/{serial}/telemetry/latest',
  async (event) => {
    const serial = event.params.serial;
    const data = event.data?.after?.data();
    if (!data) return;

    const deviceDoc = await db.collection('devices').doc(serial).get();
    const device = deviceDoc.data();
    if (!device || !device.ownerUid) return; // No owner — skip

    const userDoc = await db.collection('users').doc(device.ownerUid).get();
    const user = userDoc.data();
    if (!user || !user.fcmToken) return; // No token — skip

    const notifications: NotificationPayload[] = [];

    // Trigger 1: High temperature
    if (data.temperatureCelsius > 60) {
      const lastAlert = device.lastHighTempAlert?.toDate();
      if (!lastAlert || minutesSince(lastAlert) > 10) {
        notifications.push({
          title: 'High Temperature Alert',
          body: `Your battery temperature has reached ${data.temperatureCelsius.toFixed(1)}°C. Check your device.`,
          type: 'high_temp',
        });
        await db.collection('devices').doc(serial).update({
          lastHighTempAlert: FieldValue.serverTimestamp(),
        });
      }
    }

    // Trigger 2: Protection state active
    if (data.protectionState !== 'none') {
      const lastAlert = device.lastProtectionAlert?.toDate();
      if (!lastAlert || minutesSince(lastAlert) > 10) {
        notifications.push({
          title: 'Battery Protection Activated',
          body: `Protection triggered: ${formatProtectionState(data.protectionState)}. Check your battery immediately.`,
          type: 'protection',
        });
        await db.collection('devices').doc(serial).update({
          lastProtectionAlert: FieldValue.serverTimestamp(),
        });
      }
    }

    // Trigger 3: Low state of charge
    if (data.stateOfCharge !== null && data.stateOfCharge < 20) {
      const lastAlert = device.lastLowSocAlert?.toDate();
      if (!lastAlert || minutesSince(lastAlert) > 10) {
        notifications.push({
          title: 'Low Battery',
          body: `Your battery is at ${Math.round(data.stateOfCharge)}%. Connect a charger soon.`,
          type: 'low_soc',
        });
        await db.collection('devices').doc(serial).update({
          lastLowSocAlert: FieldValue.serverTimestamp(),
        });
      }
    }

    // Send all triggered notifications
    for (const notification of notifications) {
      await sendNotification(user.fcmToken, notification,
                             device.ownerUid, serial);
    }
  }
);
```

### 9.2 Function 2 — `onErrorCreated` (Error Push Notification)

**Trigger:** `onDocumentCreated` on `devices/{serial}/errors/{errorId}`
**Purpose:** Send push notification when a new BMS error is logged

```typescript
export const onErrorCreated = onDocumentCreated(
  'devices/{serial}/errors/{errorId}',
  async (event) => {
    const serial = event.params.serial;
    const errorData = event.data?.data();
    if (!errorData) return;

    const deviceDoc = await db.collection('devices').doc(serial).get();
    const device = deviceDoc.data();
    if (!device || !device.ownerUid) return;

    const userDoc = await db.collection('users').doc(device.ownerUid).get();
    const user = userDoc.data();
    if (!user || !user.fcmToken) return;

    await sendNotification(
      user.fcmToken,
      {
        title: 'Battery Error Detected',
        body: `${errorData.errorCode}: ${errorData.message}`,
        type: 'error',
      },
      device.ownerUid,
      serial
    );
  }
);
```

### 9.3 Function 3 — `removeDevice` (Remove Device Cascade)

**Trigger:** HTTPS Callable function
**Called by:** Flutter app from Account screen "Remove Device" action
**Purpose:** Atomically unlink device from user, delete alerts, optionally reset provisioned flag

```typescript
export const removeDevice = onCall(async (request) => {
  const uid = request.auth?.uid;
  if (!uid) throw new HttpsError('unauthenticated', 'Not authenticated');

  const { serial, forceReprovision = false } = request.data;
  if (!serial) throw new HttpsError('invalid-argument', 'Serial required');

  const batch = db.batch();

  // 1. Clear ownerUid from devices document
  const deviceRef = db.collection('devices').doc(serial);
  const deviceUpdate: Record<string, unknown> = { ownerUid: null };
  if (forceReprovision) {
    deviceUpdate.provisioned = false;
  }
  batch.update(deviceRef, deviceUpdate);

  // 2. Clear deviceSerial from users document
  const userRef = db.collection('users').doc(uid);
  batch.update(userRef, { deviceSerial: null });

  await batch.commit();

  // 3. Delete all alerts for this user + device
  // (Cannot batch delete queries — must use separate delete loop)
  const alertsQuery = await db.collection('alerts')
    .where('targetUserUid', '==', uid)
    .where('deviceSerial', '==', serial)
    .get();

  const deletePromises = alertsQuery.docs.map(doc => doc.ref.delete());
  await Promise.all(deletePromises);

  return { success: true };
});
```

### 9.4 Function 4 — `deleteAccount` (Delete Account Cascade)

**Trigger:** HTTPS Callable function
**Called by:** Flutter app from Account screen "Delete Account" action
**Purpose:** Atomically delete all user data and Firebase Auth account

```typescript
export const deleteAccount = onCall(async (request) => {
  const uid = request.auth?.uid;
  if (!uid) throw new HttpsError('unauthenticated', 'Not authenticated');

  const { serial } = request.data;

  // 1. Get user document to find paired device
  const userDoc = await db.collection('users').doc(uid).get();
  const user = userDoc.data();
  const deviceSerial = serial || user?.deviceSerial;

  const batch = db.batch();

  // 2. Null ownerUid on devices document (preserve device history)
  if (deviceSerial) {
    const deviceRef = db.collection('devices').doc(deviceSerial);
    batch.update(deviceRef, { ownerUid: null });
  }

  // 3. Delete users document
  const userRef = db.collection('users').doc(uid);
  batch.delete(userRef);

  await batch.commit();

  // 4. Delete all alerts for this user
  const alertsQuery = await db.collection('alerts')
    .where('targetUserUid', '==', uid)
    .get();

  const deletePromises = alertsQuery.docs.map(doc => doc.ref.delete());
  await Promise.all(deletePromises);

  // 5. Delete Firebase Auth user (must be last)
  await admin.auth().deleteUser(uid);

  return { success: true };
});
```

### 9.5 Shared Helper — `sendNotification`

```typescript
async function sendNotification(
  fcmToken: string,
  payload: NotificationPayload,
  targetUid: string,
  deviceSerial: string
): Promise<void> {
  try {
    await admin.messaging().send({
      token: fcmToken,
      notification: {
        title: payload.title,
        body: payload.body,
      },
      android: {
        priority: 'high',
        notification: {
          channelId: 'ohmitron_alerts',
          priority: 'max',
          sound: 'default',
        },
      },
    });

    // Write to alerts collection for in-app history
    await db.collection('alerts').add({
      targetUserUid: targetUid,
      deviceSerial: deviceSerial,
      title: payload.title,
      body: payload.body,
      timestamp: FieldValue.serverTimestamp(),
      read: false,
    });
  } catch (error: unknown) {
    if (isFirebaseError(error) &&
        (error.code === 'messaging/registration-token-not-registered' ||
         error.code === 'messaging/invalid-registration-token')) {
      // Token is stale — delete it from Firestore
      await db.collection('users').doc(targetUid).update({
        fcmToken: FieldValue.delete(),
      });
    }
    // Log other errors but don't throw — notification failure
    // should not break the function
    console.error('FCM send failed:', error);
  }
}
```

### 9.6 Deduplication Fields on `devices` Document
These fields are written by Cloud Functions to prevent duplicate notifications within a 10-minute window. Add them to the `devices` document (not defined in the main schema as they are system fields):

| Field | Type | Description |
|-------|------|-------------|
| `lastHighTempAlert` | `Timestamp` | Last time a high temperature notification was sent |
| `lastProtectionAlert` | `Timestamp` | Last time a protection state notification was sent |
| `lastLowSocAlert` | `Timestamp` | Last time a low SOC notification was sent |

## 10. FCM Token Lifecycle

### 10.1 Token Registration (Flutter App)
```dart
// In main.dart, after Firebase.initializeApp():

// Get initial token
final token = await FirebaseMessaging.instance.getToken();
if (token != null && currentUser != null) {
  await db.collection('users').doc(currentUser.uid).update({
    'fcmToken': token,
  });
}

// Listen for token refresh
FirebaseMessaging.instance.onTokenRefresh.listen((newToken) async {
  final user = FirebaseAuth.instance.currentUser;
  if (user != null) {
    await db.collection('users').doc(user.uid).update({
      'fcmToken': newToken,
    });
  }
});
```

## 11. ESP32 Write Specification

This section is provided to ensure the Flutter app and ESP32 firmware use consistent field names and types.

### 11.1 Telemetry Write (Every 30 Seconds)
```
Method: PUT (overwrite)
Path: /v1/projects/{PROJECT_ID}/databases/(default)/documents/
       devices/{SERIAL}/telemetry/latest

Body (Firestore REST format):
{
  "fields": {
    "timestamp": { "timestampValue": "SERVER_TIME" },
    "stateOfCharge": { "doubleValue": 78.5 },
    "remainingTimeHours": { "doubleValue": 3.7 },
    "voltage": { "doubleValue": 48.6 },
    "current": { "doubleValue": 12.3 },
    "dischargingWatts": { "doubleValue": 45.2 },
    "isCharging": { "booleanValue": false },
    "isDischarging": { "booleanValue": true },
    "balanceState": { "stringValue": "inactive" },
    "protectionState": { "stringValue": "none" },
    "temperatureCelsius": { "doubleValue": 28.5 }
  }
}
```

### 11.2 Device Metadata Update (On Boot + On Network Reconnect)
```
Method: PATCH (partial update)
Path: /v1/projects/{PROJECT_ID}/databases/(default)/documents/
       devices/{SERIAL}
UpdateMask: firmwareVersion,connectedSsid

Body:
{
  "fields": {
    "firmwareVersion": { "stringValue": "1.2.4" },
    "connectedSsid": { "stringValue": "HomeWiFi" }
  }
}
```

### 11.3 Error Write (On BMS Error)
```
Method: POST (create new document)
Path: /v1/projects/{PROJECT_ID}/databases/(default)/documents/
       devices/{SERIAL}/errors

Body:
{
  "fields": {
    "timestamp": { "timestampValue": "SERVER_TIME" },
    "errorCode": { "stringValue": "E001" },
    "message": { "stringValue": "Cell overvoltage detected" },
    "severity": { "stringValue": "critical" }
  }
}
```

### 11.4 Authentication (ESP32 → Firebase)
The ESP32 authenticates to Firebase REST API using a **service account JWT token**. The service account has the following IAM permissions:
- `roles/datastore.user` — read and write to Firestore
- Scoped to specific document paths via Firestore Security Rules

**The service account credentials are stored in encrypted NVS on the ESP32.** They are never transmitted to the Flutter app or stored anywhere else.
